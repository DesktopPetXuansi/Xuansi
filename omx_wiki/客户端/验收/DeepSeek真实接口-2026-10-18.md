## 发现与修复

模型曾正确返回左右颜色，但外包完整 Markdown JSON 代码块，原验证器直接解析而误判失败。[validation.py](../../../pet/ai/validation.py) 现只移除完整单一 `json`／无语言代码块包装，继续严格比较两个字段及左右颜色。额外说明、多代码块、多对象、错误颜色、额外或缺失字段均拒绝。

新增回归先复现两项失败；修复后 [验证回归](../../../tests/test_ai_validation.py) 15 项通过，验证／预检／设置定向 33 项通过。独立复核另检查八个合成边界，未发现误签证明。断言前日志改为“收到完整响应”，避免提前宣称能力通过。

失败保留：

- [首次终端证据摘要](../../../data/verification/deepseek-live-2026-10-18.json)：能力验证通过，集成 8／10。测试守卫误将生产记忆预算限为 512，阻止两次应为 2048 的请求；不是服务商返回失败。历史缓存扫描被中断，未写为通过。
- [第二次](../../../data/verification/deepseek-live-2026-10-18-recheck.json)：图片验证失败，缓存扫描也被中断。
- [第三次](../../../data/verification/deepseek-live-2026-10-18-final.json)：保存实际合成图片回复，证实代码块包装；扫描通过，整体验证仍失败。
- [修复后第四次](../../../data/verification/deepseek-live-2026-10-18-verified.json)：能力与生产冒烟均通过。原失败不覆盖，工具／记忆业务判定不放宽。

## 密钥与产物边界

密钥经确认无回显的标准输入进入进程，不在 shell 命令、进程参数、源码、普通配置、临时 JSON 或模型提示中。请求只允许官方主机的两个接口，禁止重定向，输入全部为固定合成夹具。

完整能力通过后短暂写入本轮独立 Windows 引用，生产路由实际回读；结束时已删除并确认回读为空，临时档案和回执也已删除。没有为日常运行保存该 Key，也没有把证明预置为其他用户或模式通用。

最终对 **1064 个文件**检查 UTF-8／UTF-16LE 精确字节，覆盖 Git 候选源码、`dist/`、`.omx/` 和验证资料，零匹配、零无法读取。历史构建缓存不在最终范围，前两次扫描打开文件等待的中断已保留。尚无本轮正式发行包，不能将旧产物扫描写成新包验收；正式构建仍须核对当次 payload。
