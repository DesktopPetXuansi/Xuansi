2026-09-13 按用户提供的角色设定图制作，用户指定名字为“玄司”。原图文件名为 `ChatGPT Image 2026年9月13日 19_27_57.png`；原文件保留，没有覆盖。

- `front.png`：1024×1536 RGBA 透明全身素材。
- `icon.png`：256×256 透明头像，用于托盘。
- `icon.ico`：含 16、24、32、48、64、256 像素的 Windows 图标。

制作模式：内置 `imagegen` 参考图编辑，两轮后仍得到 RGB 棋盘背景。用户明确回复“允许，使用本机脚本抠图”，再用 `scripts/prepare_xuansi_sprite.py` 本地移除背景。最终 PNG 的 alpha 极值为 0 和 255，不是把棋盘当作透明。当前素材经图像工具重新绘制，并非原图逐像素裁剪。

第一轮提示词要点：忠实提取参考图最左侧正面全身角色；保留黑发高马尾、金棕眼、黑金古风衣服、发饰和可爱比例；完整保留发梢和鞋子；去掉文字、其他视图、色卡、背景及投影；只留一个居中角色，要求真正透明 alpha。

最后一轮编辑提示词要点：只修背景，角色完全保持不变，清除画出的棋盘格，输出 alpha=0 的真实透明背景，不要把棋盘画进图片。该轮未产生 alpha，因此最终透明通道由授权的本机脚本完成。

本机处理可重跑：`.venv/Scripts/python.exe scripts/prepare_xuansi_sprite.py <第二轮输出.png> assets/xuansi`。该脚本按此素材的中性棋盘背景和头像坐标设计，不是通用抠图工具。

最初版本用 Qt 缓存 48 个轻微动作帧，状态为待机、思考、回应、休眠、向左/右移动；当时没有单独表情层或 Live2D 绑定。图像工具仅用于素材制作，运行时不需要访问图像服务。

历史许可状态（2026-09-13）：用户提供素材，当时未指定公开再分发许可，不能套用历史 NekoAI 资源的 MIT 许可；该轮仅在本机集成，没有向 GitHub 发布。

### 文件

- `xuansi-layers.psd` 和 `layers/*.png`：可在图像编辑器检查的八个分层素材（身体、头部底图、左右眼白与眼球、闭嘴、张嘴）。`layers.json` 记录层坐标、原图哈希和脸部透明孔洞修复像素数。

### 现行运行与历史核验

实际接入的参数表、独立周期、控制能力和预览资源生命周期集中在 [现行绑定说明](../../Live2D与形象/Live2D玄司制作规格.md#可编辑文件与绑定参数)，避免在素材 README 中维护另一份实现说明。下面保留各日期的关键形、像素和连续播放证据；其中早期的同周期驱动已被后续 2.8 秒头发、4.2 秒衣摆驱动替代。

2026-09-28 根据“瞳孔移动不明显”的反馈调整：眼球关键形从横向 ±7、纵向 ±5 原图像素，扩大为 ±18、±10；中立位置和眨眼不透明度保留。鼠标按眼睛到桌宠所在屏幕边缘的距离映射，越过该屏幕后停留在对应视线方向，不因其他显示器扩大映射范围。当前 160/384 像素高度均检查了九个方向；只在单屏常规 DPI 设备上运行，跨屏与混合 DPI 尚无实机验收。实现依据为 [官方 X/Y 关键形说明](https://docs.live2d.com/en/cubism-editor-manual/keyform-xydirection/)。

自动眨眼还要求 `xuansi.model3.json` 的 `Groups` 包含 `Target: Parameter`、`Name: EyeBlink`，并在 `Ids` 中列出左右眼参数。仅有参数和 `SetAutoBlinkEnable(True)` 不会自动创建这个映射。重新从 Cubism 导出时，须配置编辑器的眨眼参数并检查此组仍在；参考 [官方自动眨眼说明](https://docs.live2d.com/en/cubism-sdk-manual/autoeyeblink/)。

2026-09-27 连续播放核验：修复前刷新定时器运行，但 10 秒内眼睛开合值一直为 1；补齐此组后，真实 OpenGL 预览中的开合值覆盖 0 到 1，并出现可见闭眼帧。逐项参数检查也确认视线和口型改变画面，而转头、倾斜、呼吸参数没有对应变形；参数数量不代表已完成的绑定数量。

2026-09-29 摆动核验：保留合并的头部和身体图层，只在头部网格的 23 个后发点、身体网格的 19 个衣摆点加入 -1／0／+1 关键形。单模型 OpenGL 预览中，头发和衣摆极值都可见；衣摆极值没有拉动手臂或靴子。应用每 2.8 秒完成一个周期，并在 30 FPS 绘制帧中错相驱动两个参数；不启用独立物理模拟或新增运行依赖。

2026-09-29 补充修复：按实际 120 × 160 窗口复查发现，原 PNG 轮廓掩码会裁切超出轮廓的抗锯齿发丝。Live2D 点击区域现按窗口高度增加 3.125% 的边缘缓冲（160px 高度下为 5px）；实际尺寸预览中，窗口掩码外模型像素从摆动极值时的约 2100–2400 降至 55–139。原 PNG 形状和模型纹理保持不变。对应自动化测试仍为 `tests/test_avatar_sway.py`。

2026-09-29 头发自然摆动改进：继续使用原来的头部网格，不裁切或重画头发。为 `ParamHairFront`、`ParamHairSide`、`ParamHairBack` 添加发根、发中、发梢三组重叠权重关键形，分别以约 14、56、112 个原图像素为最大横向位移；三段参数由应用内阻尼弹簧链按 60 Hz 小步推进，根部先动，发梢逐段滞后并增幅。实际 120 × 160 OpenGL 预览检查了各段单独、左右合并极值和连续播放抽帧，未见新增明显缺口或断层。头发仍是同一张网格上的连续变形，不是独立发束或 Cubism 物理模拟。

本模型是原单图拆出的基础绑定：没有逐束发丝、手臂和衣物独立图层；头发与衣摆使用现有 ArtMesh 的局部网格变形，不是逐束头发或 Cubism 物理模拟。没有头部转动、身体呼吸或摄像头面捕。张嘴补绘和脸部局部透明修复可能不与原图逐像素相同；原始 `front.png` 保持原样。`scripts/prepare_xuansi_live2d.py` 仅针对原图 1024 × 1536 的坐标，尺寸或立绘变化后需重新校准。要重建 PSD，请在项目环境安装 `requirements-rigging.lock.txt` 后运行该脚本；此可选依赖不用于桌宠运行。

2026-09-29 动作控制接入：对话模型与朗读控制共用同一轮受限控制头，当前只公布已绑定的 `blink`。本工程尚无 `ParamArmRA` 和手臂关键形，因此 `raise_hand` 未开放；需先拆分画面左侧（角色右臂）素材、补齐被遮挡的躯干，再在 Cubism Editor 中建立并检查中立/抬手关键形，导出 SDK 5.0 目标模型后才能启用。

Editor 使用 Cubism 5.3.04，模型目标版本选为 SDK 5.0，使当前绑定数据能被锁定的运行时加载。更换导出目标前，需按 [Cubism 官方目标版本说明](https://docs.live2d.com/en/cubism-editor-manual/target-version-selection/) 和运行时兼容性重新验证。工程与运行时模型均保留在本目录；构建应用前还需核对运行库中 Cubism Core 的适用许可，详见根目录 [第三方许可记录](../../项目/THIRD_PARTY.md)。

## 玄司久置拔刀姿态

素材位置：[assets/xuansi/idle-blade/](../../../assets/xuansi/idle-blade/)。下文目录和文件名均指该素材目录，图片和制作脚本保持原位。

运行说明核对日期：2026-10-11。版本状态见 [文档索引](../../README.md)，一般形象操作见 [使用指南](../../客户端/使用指南.md#形象与预览)。本轮未修改 PNG 或模型。

这组透明 PNG 用于默认 Live2D 玄司的单次久置待机动作。`reach.png` 抬手够刀柄，`grip.png` 握住刀柄，`draw-half.png` 半拔，`drawn.png` 展示完整拔出的长刀；播放时按相反顺序收刀。它不属于对话模型可调用的原生抬手动作。

计时由 [idle_action.py](../../../pet/idle_action.py) 与 [app.py](../../../pet/app.py) 的系统最后输入时间驱动：持续五分钟无键鼠输入且满足默认 Live2D、idle、桌面可用、无忙碌任务和无收音等资格后才播放；资格中断重置。系统输入检测只读取时间戳，不读取键盘正文。

现有 PSD 的身体层合并了双臂。运行时使用全身透明姿态，可以避免单独叠加手臂时留下原手臂重影。姿态显示时清空 GL 缓冲，只显示姿态帧，暂停底层 Live2D 参数更新和绘制；动作结束或用户有键鼠输入后淡出姿态并恢复模型。默认尺寸下四帧缓存约 0.29 MiB，姿态素材在初始化、尺寸变化或形象重新加载时预读并缩放，动画播放过程中不逐帧读盘。

2026-10-07 更正：原说明“Live2D 模型本身仍在下层正常更新”对应早期实现，已按当前 [Avatar 入口](../../../pet/avatar.py) 更正；本轮源码拆分后，暂停底层绘制的分支见 [Live2D 绘制](../../../pet/avatar_live2d.py)，姿态与淡出见 [拔刀实现](../../../pet/avatar_idle_blade.py)。暂停底层绘制的修复已包含在 0.5.0 及后续版本，源码拆分纳入 0.5.5。此次默认形象预览不加载拔刀姿态，不会因预览窗口久置自动播放此动作，见 [预览修复验收](形象演进验收.md#record-3a738cca)。

姿态图基于 `assets/xuansi/front.png` 制作，作为玄司美术素材的衍生图受 `assets/xuansi/LICENSE` 所列权利约束。源 PNG、Live2D PSD、网格和纹理均保持不变。
