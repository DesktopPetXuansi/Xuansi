## 桌宠控制中心合并

需求日期：2026-10-15。用户要求把软件控制菜单合并为一个页面，减少分散的页面和窗口。基于当前 Python/PySide6 6.11.2 实现，继续使用原生 Qt，不增加依赖。

后续调整：用户提供 Chrome 顶部标签栏截图，现行导航按 [浏览器式标签栏任务](#record-44223a59) 实现；下方纵向分区方案与勾选保留为首阶段记录。共用一个控制窗口及业务生命周期约定继续适用。

<a id="record-913ad1cd-方案与边界"></a>
### 方案与边界

- 一个控制中心承载对话、人设、长期记忆、语音与行为、模型参数、形象、官网资源、上传和日志。取消原标签页与多层控制菜单，分区可分别展开；定位操作只滚动同一页面。
- 顶部集中连续对话、朗读、看屏幕、休眠、停止和声音回避，底部提供统一保存与状态。使用现有绿色和暖白样式，保持键盘可达、窄窗口可用。
- 默认将托盘和快捷键统一到控制中心；文件选择、浏览器账号授权及桌宠本体继续使用各自必要的系统/桌面交互。
- 配置仍经原事务保存，关闭前保留无效或保存失败的草稿；形象更换仍不打断对话。数据位置、账号权限、上传协议与模型运行核心保持原契约。
- 形象分区隐藏时停止预览并拒收迟到导入；官网任务在收起控制中心后可继续，取消通过明确按钮进行；退出应用仍等待后台线程完成。已上传版本的入库重试沿用同一凭据和 receipt。

### 官方依据

- [QDialog 父对象与窗口标志](https://doc.qt.io/qt-6.11/qdialog.html#details)：有父对象的对话框仍是窗口，嵌入需明确清除 Dialog 标志并处理接受/拒绝语义。

<a id="record-44223a59-界面与实现"></a>
### 界面与实现

- 顶部横向圆角标签，选中项与内容区域使用一致背景，沿用暖白、浅绿与深绿，不照搬截图中的深色。

## 桌宠客户端直接上传 Live2D

用户已选择在现有 desktop-ai-pet 客户端中完成上传。目标流程：打开官网资源库，点击上传本地模型；首次通过浏览器连接官网账号，选择模型文件夹或入口文件，确认默认资料后上传。

<a id="record-0ce7fbe5-方案"></a>
### 方案

- 复用 PKCE、Windows 凭据管理器和官网现有资源/版本/上传接口。
- 上传操作显式申请 `resources:read resources:write`；既有只读令牌不升级，账号、管理员、发布和删除资源权限不开放。
- 自动收集 `.model3.json` 引用的运行文件，保留相对目录，只打包模型所需文件。压缩、磁盘与网络 I/O 在后台执行，源文件不改动。
- 默认名称来自模型入口文件名或选择的目录名、作者来自本人账号、版本号为 `1.0.0`；许可使用现有默认提示，用户可编辑。
- 上传后等待官网校验，自动设置当前版本并加入本人的资源库。提供进度、取消、错误说明和官网查看入口。

<a id="record-0ce7fbe5-任务与验收"></a>
### 任务与验收

- [x] 本地模型整理：支持入口文件和模型文件夹，忽略编辑工程和无关文件；缺引用、多入口、越界路径、链接、超限均在上传前失败；不修改源模型。
- [x] 客户端上传流程：异步流式上传；验证后自动设当前版本与入库；取消和失败释放上传配额，临时文件清理；存储上传不泄漏官网凭据。
