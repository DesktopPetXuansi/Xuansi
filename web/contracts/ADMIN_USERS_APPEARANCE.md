# 用户管理与形象浏览增量约定

2026-10-24：修复用户管理只能读取最新20个账号的问题，并调整官网“挑选形象”的布局和实际资源分类。保留管理员鉴权、原账号停用与撤权、资源上传和客户端授权能力，不新增应用依赖或真实资源。

## 用户管理

GET `/api/v1/admin/users` 继续返回 `data: User[]`，增加 `meta: {nextCursor: string|null, total: number}`。旧调用方可继续忽略meta。查询参数：

- `limit`：默认20，1～100；`cursor`为不透明游标，最大1024字符，不包含邮箱或搜索词。
- `search`：最多120个Unicode码点，昵称或邮箱的忽略大小写字面子串，`%`、`_`和反斜杠不作SQL通配符。
- `role`：空、USER或ADMIN；`status`：空、ACTIVE或DISABLED。

先对全部账号筛选和计数，再按 `(created_at DESC, id DESC)` 稳定分页，不能在前20人上做前端搜索。total不受cursor影响；无效查询返回400。只有网站管理员可读写，普通用户403、匿名401，OAuth客户端授权不获管理员能力。响应仅使用既有UserView，密码和令牌不返回；不把邮箱或搜索词写日志。管理员本人不能停用自己，停用其他账号仍撤销该账号既有授权。

## 形象与配套资源

GET `/api/v1/resources` 与既有个人资源列表支持可选查询 `group`：APPEARANCE限定MODEL/IMAGE/ANIMATION，ADDON限定MOTION/EXPRESSION。与原kind、search、tag同时作用，先过滤再执行原稳定ID分页；无效group返回400。不传group仍返回原全资源范围，保持客户端和创作者管理兼容。

公开网页默认APPEARANCE。动作和表情为配套资源，不能当作可独立使用的桌宠；个人“我的资源”默认不加group。查询条件与分页保存在网页URL，切换组/类型清空cursor。用户可以刷新和后退恢复浏览条件，旧查询可取消。
