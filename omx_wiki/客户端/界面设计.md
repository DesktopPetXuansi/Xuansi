## 2026-10-16 调研依据

调研时窗口已经将九个页面整合到同一控制中心，横向浏览器式标签是已有明确选择，继续保留。主要问题来自空间和操作层级，不需要迁移框架。

已实际运行当前 Qt 控件和 Live2D，并补跑 `DesktopPet` 协调流程。详细证据见 [界面调研记录](验收/界面调研-2026-10-16.md)。网络、对话、账号和音频输入使用临时数据或替身，不能据此声称真实模型、麦克风或官网闭环已复验。

| 实测现象 | 对用户的影响 | 建议 |
| --- | --- | --- |
| 880×760 下顶部 225px、底部 96px，页面仅 439px | 所有页面都为六个常用按钮和保存区让位 | 顶部保留紧凑状态与连续对话/休眠，其余对话操作就近放置；底部缩为一行 |
| 聊天记录高 200px，放大到 1040×800 后仍为 200px | 放大窗口没有换来更多阅读空间 | 记录区按剩余高度伸展，输入区固定可达 |
| 520×480 时聊天页外层滚动 181px，输入框初始不在视口 | 用户必须先滚动才能发送 | 对话取消外层整体滚动，记录自身滚动，输入区保留 |
| 偏好/模型/形象/资源在默认尺寸均需纵向滚动 | 低频说明和聊天按钮挤压核心表单 | 压缩公共区，按任务分组，长表单仍可正常纵向滚动 |
| “保存全部设置”只读取三组配置表单 | 用户容易以为记忆、形象也已保存 | 改为“保存设置”，说明范围；保留独立保存/应用动作 |

上述表格保留调研时的100%缩放基线。2026-10-16改版后在880×760下内容区607、聊天记录407逻辑像素，最小窗口输入完整可见；完整测量和前后截图见当轮验收记录。后续默认尺寸与验证以下方2026-10-18约定为准。

2026-10-18 用户随后批准完整形象更换流程：本地导入（图片、动图、导出的 Live2D 运行文件或唯一模型文件夹）或在线挑选 → 下载/整理并预览 → 使用这个形象自动保存。公共形象列表匿名读取，自动选最新可用版本；动作/表情仍在“更多资源”。压缩包和编辑工程给出先解压/导出的说明。“上传分享”保留创作者流程，本机换形象不依赖上传。

采用“暖白工作台”：延续草绿与现有玄司形象，使用更清楚的中文字号、对齐和轻分隔。减少整块深绿色按钮和空占位；深绿用于当前主要动作，开关通过文字、勾选及轻背景表达。

视觉参数沿用 [DESIGN.md 的 Visual language](../../DESIGN.md#visual-language)。Qt 的 token 在现有 `pet/panel_style.py` 内集中维护，字体继续使用 `pet/theme.py`。复用原生控件及 QSS，不新增主题框架、WebView、外部字体或依赖。

### 公共结构与对话

1. 顶部主标签依次为对话、人设、记忆、语音与行为、模型设置、更换形象、运行日志；宽度不足继续左右滚动，Ctrl+Tab/反向只循环这七项。固定页面仍有九个，官网资源与模型上传从形象页进入，保持高亮形象标签；点击形象标签或“返回形象”可返回。
2. 标签下是一条紧凑状态区：玄司、真实运行状态、连续对话、休眠。长状态允许换行，忙碌与错误不被省略成含糊色点。
3. 对话页使用可伸展记录区；输入与发送始终可见。看屏幕、朗读、声音回避、停止回复放在输入附近，状态更新仍走现有信号；全局保留连续对话与休眠。
4. 全局底栏保留保存状态、“保存设置”“收起”，降低视觉权重。即使配置数值未改变，显式保存入口仍保留原行为，包括恢复已保存的朗读偏好。

历史布局方向草图仅用于确认层级与风格，聊天内容是固定样例，并非运行截图。本机忽略证据路径为 `data/verification/desktop-design-2026-10-16/proposal/layout-draft.png`，未提交到 Git，不随源码导出或安装包交付；真实基线与草图当时分目录保存。颜色、行高和状态说明最终以原生运行验证。

### 各页面职责

| 页面 | 调整范围 | 保留边界 |
| --- | --- | --- |
| 人设 | 名字、人设、回复习惯清楚分组；编辑区域随高度扩展 | 原字数限制、校验与草稿保存 |
| 长期记忆 | 编辑器占主要空间；保存与清空保持可见，提示本机存储 | 独立保存/清空仍取消当前任务并清短期上下文；默认不增加确认流程 |
| 语音与行为 | 分为声音、麦克风、观察与行为；说明就近，窄窗字段换行 | 全部选项、试听、设备缺失保留、切换音色默认值 |
| 模型设置 | 当前源码包含推理策略、本地档位/后端/目录、在线预设/Key/合成验证、独立云端资料授权，以及回复参数与快捷键 | API-only 保存不强制本地权重；凭据独立事务、证据绑定配置、取消/迟到回调及草稿保留 |
| 更换形象 | 本地导入或在线挑选 → 预览 → 使用这个形象；我的形象汇总本机候选，当前使用与预览分别显示 | 图片/动图/导出 Live2D 自动识别；使用自动保存，失败保留原形象；切页保留候选并暂停 GL |
| 官网资源（形象页次级入口） | 官网连接、可下载资源与版本、本机资源分组；明确未加载/空/失败 | 浏览器授权、下载应用、动作/表情重置、恢复默认、取消 |
| 模型上传（上传分享入口） | 一页内按选择模型、填写信息、上传与入库组织；进度与取消就近 | 作者/许可/版本、换站校验、继续入库、官网查看、后台上传 |
| 运行日志 | 筛选紧凑，文本区填充；错误有清楚文本和焦点 | 最近 1000 行、级别、跟随/刷新；隐藏停止轮询 |

## 当前源码的组件与线程边界

完整生产模块归属统一维护在 [架构职责映射](../项目/项目文档.md#模块职责与依赖边界)，此处只约束界面接口：

| 组件 | 负责内容 | 不跨越的事务边界 |
| --- | --- | --- |
| `panel.py`、`control_navigation.py`、`control_section.py` | 固定九页、七个主标签及次级导航、页面可见性与独立滚动 | 切页不自动保存，不重建 GL 父级 |
| `panel_chrome.py`、`panel_content.py` | 紧凑状态/底栏、三行转写预览、对话输入附近操作与可伸展记录 | `ResourceStatus` 持续保留实际模型，上传进度和资源轮询不能覆盖它 |
| `panel_settings.py`、`settings_forms.py`、`preferences.py`、`model_page.py`、`ai_setup_form.py` | 保存快照、分组/折叠表单、标签关联、模型配置步骤与窄窗换行 | 统一配置保存与热键事务继续由原协调层执行 |
| `ai_page.py`、`ai_tasks.py` | 模型策略/Key 草稿、设备检测和合成能力验证 | 网络/探测在 `QThreadPool`；Qt 主线程只收信号；请求 ID/摘要/代次阻止迟到覆盖 |
| `appearance_hub.py`、`appearance_layout.py`、`appearance_preview.py` | 形象步骤、候选/当前身份、真实独立预览与明确使用 | 预览成功才启用使用；不自动应用，不以静态回退冒充成功 |
| `appearance_flow.py`、`appearance_sources.py`、`appearance_apply.py` | 统一来源、后台任务交付、形象保存与严格试载 | 保存成功再改 Avatar，失败只回滚形象三字段；不接管对话/收音和其他设置草稿 |
| `platform_layout.py`、资源/上传页面 | 共用原生布局、账号/资源/上传动作呈现 | OAuth、任务取消和上传入库回执仍由原页面及服务持有 |
| `panel_style.py`、`theme.py` | 唯一 QSS 与本机中文字体 | 不另建重复 token 或主题框架 |

模型页隐藏时取消本次合成验证、使设备探测代次失效，保留配置和 Key 草稿；资源上传隐藏后继续运行。未安装语音组件时禁用对应偏好/引擎/音色/试听，保留已存值，API 对话不自动安装语音或启麦。默认内存轮询、资源任务状态和当前模型状态分别更新，不因共享底栏而丢失实际推理位置。

本次形象流程的任务与验收边界见 [完整流程任务](任务/形象更换流程-2026-10-18.md)。该流程及严格加载失败回滚纳入0.7.1；2026-10-18的源码和本机local-preview验收保留当时的交付边界，安装包及公开验证以 [0.7.1 发布验收](../发布与安装/验收/安装包0.7.1发布验收.md) 为准，不沿用旧截图宣称新流程通过。

本轮新增推理设置的验证证据见 [安装前适配与多模型验收](验收/安装前适配与多模型-2026-10-18.md)，模型/凭据保存规则以 [配置与数据](配置与数据.md) 为准。0.7.1 安装包和本地源码的交付边界见 [安装与发布](../发布与安装/安装与发布.md)，不把旧 UI 替身测试扩展成新发行证明。

## 交互与性能约束

- 不改变业务事务：配置保存、人设草稿、记忆、应用形象、官网地址/账号、上传仍按原有边界执行。关闭窗口不等于退出；配置有修改才保存，失败保留窗口和草稿。
- 运行时朗读开关与已保存默认偏好分别说明；“本次附图”不能被解释为关闭全部语音自动附图。
- 使用固定页面实例；不重复构造 OpenGL 子控件，不在切页时迁移 GL 父级。隐藏页停止当前已定义的预览和日志轮询，上传继续到完成或显式取消。
- 用户操作使用原信号槽。耗时 IO 保持后台，Qt 控件只在主线程更新；不以每次编辑重绘全应用样式，不为视觉动效增加常驻计时器。
- 保留 Tab/Shift+Tab、Ctrl+Tab/反向、Enter 发送、Esc 收起、托盘与全局热键。增加可见焦点、中文辅助名称；图标不作为唯一操作说明。
- 清空记忆确认/撤销属于可选交互变化，本方案默认不包含；若需要，单独确认后补充回归。

## 验收目标

- 功能矩阵逐项保留：九页、单控制窗口、原有系统文件选择/浏览器授权、托盘、热键、保存/失败/取消边界。
- 默认720×560、就绪/无错误状态下，内容页高度目标≥420px、聊天记录高度≥230px；880×760及1040×800时继续增长。当前实测427/243px；此前880×760的607/407px只作历史基线。
- 520×480 与 560×660 的输入和发送无需外层滚动即可操作；各页面无整体横向滚动。长设置/资源页允许纵向滚动，长路径可在控件内查看。
- 100%/125%/150% 缩放下检查文字、按钮、下拉列表、焦点和预览；真实系统缩放与环境模拟分别记录。
- 至少覆盖九页，以及空对话、回复中可停止、未保存/保存中/失败、聆听/暂停/休眠、资源空/失败、上传进行/完成/取消、形象预览切出重返。
- 前后使用相同固定样例、页面、窗口逻辑尺寸与 DPR。本轮内容截图仅采用应用自身可见 `QWidget.grab()`，避免抓取其他应用桌面；GL 用实际预览和必要的 framebuffer 采样核对。标记替身业务，不冒充模型或服务器验收。
- 验证不记录用户聊天/凭据；不打开物理麦克风、不抓其他应用画面。真实模型、物理音频和真实官网业务如需复验，另列环境与范围。
