## 1. 移除与替代

| 功能 | 移除的实现 | 当前实现 |
| --- | --- | --- |
| 语音自动附图 | `VOICE_SCREEN_PATTERN` 及两种识别入口的正则匹配 | `LocalEngine.needs_screen` → `model_semantics.request_choice` → Qwen 判断 `screen` |
| 相关长期记忆 | `MemoryStore.context` 的关键词拆分、匹配得分、最近记录回退 | 原文快照 → `LocalEngine.select_memory` → `model_memory.retrieve_memory` → Qwen 选择相关原文 |
| 保存澄清 | `LocalEngine.chat` 的固定确认句及提前返回 | `_reply_settings` 构造专用澄清任务 → 真实正文请求/SSE → 模型生成针对事项的询问 |
| 自动 TTS 选择 | `_CJK_TEXT`、`_LATIN_WORD` 及字符启发式 | 流式正文前由模型控制决策选择 `tts`；观察与试听在完整正文产生后由 `choose_tts` 判断 |

继续使用既有 Qwen3.5-4B Q4_K_M、mmproj 和 llama.cpp b10930。Paraformer/SenseVoice 负责 ASR，sherpa-onnx 的 Melo/Kokoro ONNX 模型负责实际波形。没有新增模型或云端 API。

## 2. 实际调用链

### 2.1 实时与整句语音

实时路径：`Microphone._run` → `OnlineInput.feed/_decode` → Paraformer `decode_stream` → `VoiceUpdate` → `DesktopPet.on_voice_update` → `Runtime.accept_voice` → `LiveDialogue.accept` → `Runtime.ask/_replace/_conversation` → `conversation.converse`。

整句路径：`Microphone._run` → `Segmenter.feed` → `DesktopPet.on_segment` → `Runtime.ask` → `converse` → 工作线程执行 `AudioModels.transcribe` → SenseVoice `decode_stream`。

随后两条路径共用 `converse`。未显式附图且有有效候选鼠标坐标时，等待 `engine.needs_screen(settings, text, history)`；模型返回 true 才调用 `desktop.capture_screen`。显式勾选仍直接附图，坐标缓存、观察范围和设备门控保持。模型判断在后台事件循环执行。

源码：[microphone.py](../../../pet/microphone.py)、[live_input.py](../../../pet/live_input.py)、[app.py](../../../pet/app.py)、[live_dialogue.py](../../../pet/live_dialogue.py)、[conversation.py](../../../pet/conversation.py)、[inference.py](../../../pet/inference.py)、[model_semantics.py](../../../pet/model_semantics.py)。

### 2.2 文字、语音和观察的记忆链

`converse` → 工作线程执行 `MemoryStore.context(text, limit=6000)` → 原文快照 → `LocalEngine.select_memory` → `retrieve_memory` → `_fit_context/_capacity_prefix/_scan` → `_select` → `POST /v1/chat/completions` → 验证 ID、出处和预算 → 相关原文注入正文系统消息。

全部候选都可参与检索。长记忆按容量分片并保留少量重叠，每批使用 `/v1/chat/completions/input_tokens` 对完整请求及真实聊天模板计数。旧历史按完整用户轮次边界裁剪，保留本轮问题；输出预算随剩余容量调整。超过最终 700 字预算时继续由模型筛选。无关返回空，非法、杜撰或截断结果报错，不回退关键词、最近记录或固定摘要。

源码：[memory.py](../../../pet/memory.py)、[model_memory.py](../../../pet/model_memory.py)、[conversation.py](../../../pet/conversation.py)、[inference.py](../../../pet/inference.py)。

### 2.3 控制、保存授权与正文

`generate_reply` → `ControlCallbacks` → `LocalEngine.chat` → `_understand_control` → `decide_control` → Qwen 确定 `voice/motion/memory_intent/memory/tts`。

有保存候选时，`decide_control` 再调用 `verify_memory_authorization` 复核。通过后 `chat` 等待 `remember` 回调 → `durable_io` → `MemoryStore.remember` 实际写入，再请求正文。待确认时不写入，`_reply_settings` 让模型询问保存授权或缺失事项；正文温度仍使用原设置。

正文走 `POST /v1/chat/completions`，可采用 SSE → `read_completion` → `SpeechDirective` 去除已确定的控制头 → `receive` 同步文本与语音。受限语法只约束控制头和合法能力，不按用户文字推断意图。观察入口不执行语音或动作控制。

源码：[conversation.py](../../../pet/conversation.py)、[inference.py](../../../pet/inference.py)、[model_control.py](../../../pet/model_control.py)、[speech_control.py](../../../pet/speech_control.py)、[text_stream.py](../../../pet/text_stream.py)、[memory.py](../../../pet/memory.py)。

### 2.4 TTS 与非流式入口

流式路径：`chat` 先调用 `ControlCallbacks.apply_tts(decision.tts)` → `SpeechStream.feed` 分段 → 工作线程执行 `AudioModels.synthesize_selected` → `synthesize` → `_load_fast_tts/_load_tts` → ONNX `tts.generate` → 播放与口型响度。

观察和试听路径：`Runtime._speak` → `LocalEngine.choose_tts` → Qwen 对完整正文判断（显式 natural 直接保持）→ `synthesize_selected` → 实际波形。

正文开始后，合成线程不再调用同一个语言模型，避免与单槽 llama.cpp 服务互相等待。自动选择的 Kokoro 只有加载失败时允许回退 Melo；显式 natural 的失败及已加载模型的生成错误继续传播。

源码：[runtime.py](../../../pet/runtime.py)、[streaming_speech.py](../../../pet/streaming_speech.py)、[speech_output.py](../../../pet/speech_output.py)、[audio_models.py](../../../pet/audio_models.py)。

## 3. 兼容性和保留的程序控制

用户入口、Qt 信号、配置字段及持久化 JSON 格式保持。`VoiceUpdate.with_screen`、`ControlDecision.tts` 和 `ControlCallbacks.apply_tts` 均为末尾带默认值的扩展，原位置参数仍可使用；原入口没有新增必选参数。

内部职责有明确迁移：同步 `MemoryStore.context(query, limit=700)` 保留签名和字符串返回值，改为原文快照。生产调用取 6000 字，再异步让模型选最多 700 字。`select_tts_engine(text, requested)` 保留签名，只执行上层已确定的选择。直接调用这些低层函数不再获得旧的启发式语义行为；应用调用链已接到模型模块。内部控制 JSON 新增 `tts`，正文控制头仍为 `[voice:...][motion:...]`。

取消、清空记忆、新请求、配置变化及休眠继续校验代次。模型预处理取消时回收本实例拥有的服务，完成后再次验证代次，不让旧结果继续截屏、生成或播放。开麦预热只准备缓存，不执行合成示例的模型建议。

保留以下程序逻辑，它们不代替模型做语义判断：

- 音频 RMS、静音等待、最长话段、播放分段和设备控制。既有 SenseVoice 没有流式神经 VAD，Paraformer endpoint 也含时长规则；纯神经 VAD 需要额外权重，本次不新增。
- 鼠标事件和观察节流、状态及执行权限门控、敏感记忆过滤、协议枚举、原文校验、Markdown/模型标记清理。
- Live2D 插值、自动眨眼、视线、口型、久置动作计时，以及静态/动图播放。
- TTS 配套 FST、词典和 G2P，它们属于语音推理的文本规范化组件，实际波形由 ONNX 模型生成。
