# 反馈私有对话

用户批准在现有反馈流程中增加管理员回复、用户补充和对话记录。本轮交付站内功能，邮件通知后续单独加入。保留匿名提交、管理链接、公开审核和撤回契约，不创建默认账号或暴露管理员个人身份。

2026-10-24 扩展：登录用户改为账号内反馈聊天，新访客只提交给后台，不生成新的管理链接或本机历史；本页的凭据接口继续服务旧链接。账号归属、昵称、读水位和新增工作台以 [账号反馈聊天](FEEDBACK_CHAT.md) 为准，旧私信存储与审核/撤回规则继续复用。

## 使用与状态

- 管理员在反馈卡片点击“回复用户”查看对话，发送回复或回复并标记已解决。普通回复将 NEW 转为 IN_PROGRESS，其余进度保留；明确解决时转为 RESOLVED。
- 持有有效管理凭据的用户可在原管理页查看对话、补充说明。补充将进度设为 NEW，界面明确说明会重新进入待处理。
- 对话中管理员统一显示为“开发者”，用户显示为“你”或“用户”。不返回管理员姓名、邮箱、用户编号或登录会话。
- SPAM、WITHDRAWN、WITHDRAWAL_REQUESTED 或没有原始管理凭据的旧反馈不能新增消息。旧客户端提交继续正常受理，不为旧记录补造管理凭据。
- 初始问题与对话正文分开存储；对话永不进入 GitHub 投递，也不修改原反馈的公开许可。

## 接口

所有路径带 `/api/v1` 前缀。读写均沿用现有 no-store、CSRF、管理员会话与匿名 IP 速率限制。匿名管理凭据只通过 JSON 正文传递。

| 路径 | 用途 | 请求 |
| --- | --- | --- |
| GET `/admin/feedback/{id}/messages` | 管理员读取 | cursor、limit 查询参数 |
| POST `/admin/feedback/{id}/messages` | 管理员回复 | `{body, resolve?: boolean}`，稳定的 Idempotency-Key UUID |
| POST `/feedback/{id}/messages/query` | 用户读取 | `{managementToken, cursor?: string, limit?: number}` |
| POST `/feedback/{id}/messages` | 用户补充 | `{managementToken, body}`，稳定的 Idempotency-Key UUID |

读取返回 `{data: FeedbackConversation, meta: {nextCursor: string | null}}`。默认最新20条、最多50条；每页内部按时间升序显示，cursor加载更早消息。分页游标绑定当前反馈，不能串用。

`FeedbackConversation` 为 `{id, title, description, status, moderationStatus, canReply, messages}`。初始问题仅管理员或有效管理凭据持有者可读，不包含联系方式。`messages` 的元素为 `{id, authorRole: "ADMIN" | "USER", body, createdAt}`。

发送返回 `{data: {message: FeedbackMessage, feedbackStatus: FeedbackStatus}}`，新消息201、幂等重放200。`message` 在重放时保持同一消息，`feedbackStatus` 始终表示响应时父反馈的当前状态；重试不覆盖其间发生的用户补充或管理员处理。正文去首尾空白后1至4000字符。未知字段、非法编号/游标、超大请求及无效凭据拒绝；错误沿用现有响应格式。不存在反馈与无效匿名凭据统一403，管理员不存在记录返回404。

## 存储、并发与隐私

- 新消息表外键关联 feedback；分页索引为 `(feedback_id, created_at, id)`，幂等唯一键按反馈、发送角色与请求编号隔离。请求摘要绑定正文、操作和真实管理员身份，重试同一意图返回同一消息，不重复改变状态；同编号不同内容返回409。
- 消息写入、状态更新、审核及撤回使用同一反馈父行锁。消息写入与审计在同一事务提交；审计和日志仅包含动作、编号，不记录正文、凭据、联系方式或管理员邮箱。
- 用户消息写入还受数据库持久化额度限制，幂等重放不重复计数。管理员发送同样有合理的频率限制。读取不轮询，按用户操作刷新与加载更早对话。
- 撤回请求立即清空私有对话正文；最终撤回继续清空初始正文、联系方式、诊断。保留必要消息幂等骨架与状态，不允许重试恢复已清理内容。读写需与撤回保持一致，WITHDRAWN 与 WITHDRAWAL_REQUESTED 不返回已清理的消息。
- 无管理凭据的旧反馈不能生成新的访问凭据。只允许拥有原管理链接的人访问对话；邮箱联系方式本身不赋予访问权。

## 任务与验收

1. 固定 OpenAPI 与生成类型；增加迁移、受权分页及事务消息写入，先以真实隔离数据库测试确认旧实现失败，再实现。
2. 实现后台回复、管理页对话和用户补充；失败保留草稿和幂等请求，保存时锁定关联状态/筛选/撤回操作；鉴权失败立即隐藏已读对话。
3. 更新反馈成功提示、隐私说明和接口文档；验证原注册、下载、反馈、公开审核、撤回及旧客户端未受影响。
4. 运行类型/静态检查、真实数据库测试、浏览器回归、生产构建与独立审查，通过后沿现有 main 自动部署，复验正式版本与桌面/手机页面。

必须覆盖：角色与token隔离、分页、XSS纯文本显示、同意图重试/冲突、状态同步、无凭据旧记录、垃圾/撤回状态关闭、撤回与消息并发、投递不包含私信、权限失效和取消读取不恢复旧缓存。所有验收使用合成内容，不读取真实用户反馈或以真实管理员会话代测。
