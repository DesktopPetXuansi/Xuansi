### 注册密码与邮件提示回归修复

2026-10-13，用户实际注册发现前端提示10字符、后端要求12字节，以及真实邮箱没有收到验证码。根因分别是规则重复定义和开发邮件送达位置不清晰；邮件worker已完成任务，当前实际收件服务为Mailpit。

修复后，Go密码创建/重置/修改共用12～128个Unicode码点规则，前端从公开 `/api/v1/auth/config` 获取同一边界。登录不应用新建密码的最小长度，已有密码摘要保持兼容。注册、找回及邮箱验证页面在本地Mailpit模式下显示“打开本地收件箱”和验证链接说明；生产或真实SMTP模式隐藏此入口。配置接口不返回SMTP账号、密码或服务器连接信息。API当前契约增至47路径、56操作。

验证：先以失败测试复现中文字节计数、Emoji上限、配置缺失和页面10字符提示；修复后Go全套测试、vet和编译通过，前端typecheck、lint与生产构建通过，限定独立复审0问题。`node web/scripts/verify-auth-regression.mjs` 的6项浏览器检查通过，覆盖10/11位、中文/Emoji、12字符真实注册、worker投递、一次性链接确认、账号设置/重置一致、旧密码登录请求兼容，以及模拟SMTP模式与动态服务端规则。Next构建使用 `NEXT_TELEMETRY_DISABLED=1`，避免本机用户配置文件的原子改名错误；没有修改全局用户配置。

邮件验证仍为有效期1小时的链接，并非数字验证码；上述回归阶段使用Mailpit。注册成功提示明确为排队发送或本地收件，不能据此声称真实邮箱已经收到邮件。字符计数依据 [Go utf8](https://pkg.go.dev/unicode/utf8#RuneCountInString) 和前端字符串码点迭代，避免字节与UTF-16长度再次不一致。

### 复审修复

- 管理员停用后，所有者不能自行恢复；已有下载票据也重新检查停用和授权撤销。
- 资源库数据库失败返回错误，资源、版本依赖与发行安装包批量加载，单个版本不扫描整个版本列表。

- CSRF 准备复用合法已有 cookie，避免并发请求互相覆盖令牌；针对旧令牌与当前 cookie 的写入回归通过。
- 前端资料编辑不发送仅创建时允许的 kind，版本草稿编辑只发送 releaseNotes，可选表单空值不变成字符串 `null`。
- Go/Python 对空的可选 Cubism 引用、最低版本、文件数与允许附件类型统一，必需引用仍拒绝空值。共享夹具和两端回归通过。
- 客户端模型切换、平台设置持久化、窗口关闭与后台取消保持一致，外部模型不暴露玄司专用动作。
- Go 工具链、JOSE 和 OpenTelemetry 升级到包含安全修复的版本，静态 WebP 明确注册解码器。生产代理保持 `no-referrer`，避免一次性邮件链接作为来源泄露。

## 客户端 Live2D 直接上传验收 2026-10-15

记录日期：2026-10-15。本文记录本次开发和复查的结果；运行状态与发行状态均为当日快照。

<a id="record-a1bcbba8-需求与交付状态"></a>
### 需求与交付状态

用户希望通过现有 desktop-ai-pet 桌宠客户端连接官网并直接上传本地 Live2D，减少网页手工创建资源和打包的步骤。实现已提交为 `f9fedf7 feat(client): 支持桌宠直接连接官网并上传本地 Live2D 模型`，任务清单四项均已完成。本次复查未发现漏改或漏提交的功能代码。

当前源码客户端可以使用新入口；公开 0.5.6 安装包尚未包含官网资源接入和上传功能。未制作或发布新安装包，未部署公网服务。资源商店等原规划中的扩展能力不计入本次完成范围。

<a id="record-a1bcbba8-用户操作"></a>
### 用户操作

1. 使用项目“启动桌宠”入口运行当前源码，右击托盘选择“官网：上传本地模型”，或从官网资源库窗口点击“上传本地 Live2D 模型”。
2. 首次在浏览器登录已验证邮箱的官网账号，明确同意“允许上传模型”；有效授权会复用。
3. 选择模型文件夹或 `.model3.json` 入口。名称、作者、版本、许可预填，用户应核对原作者和许可；文件夹内存在多个入口时需选择具体文件。
4. 客户端自动整理运行文件、创建资源和版本、上传并等待校验，成功后设置当前版本并加入本人资源库，可在官网查看及重新下载应用。

完整使用说明见 [客户端上传](../../客户端/使用指南.md#官网资源与本地上传)。只有 `.cmo3` 编辑工程时，需要先在 Cubism 中导出运行文件。

<a id="record-a1bcbba8-关键实现与边界"></a>
### 关键实现与边界

- 授权复用浏览器 PKCE、随机回环回调和 Windows 凭据管理器。上传明确申请 `resources:read resources:write`，既有只读令牌不自动升级；刷新保留原权限，访问受本人资源归属约束。
- 写权限只覆盖所需资源、版本、上传和入库操作；不开放账号管理、管理员、发布或删除资源权限。Bearer 更新资源仅允许 `currentVersionId`。
- 打包和安装共用明确的 Cubism 文件引用规则，只收集入口、模型数据、纹理、物理、姿态、显示信息、用户数据、动作、表情和动作声音。未知元数据附件、工程和私人笔记不收集，源文件只读。
- 整理阶段拒绝缺失引用、路径越界、符号链接和 Windows 目录链接、大小写冲突与超限；入口 JSON 上限 8 MiB、文件数上限 2048、总文件和最终包上限 512 MiB。目录搜索不递归进入链接。
- 文件整理和网络请求在后台执行，使用分块流式 I/O，Qt 信号更新进度。外部对象存储仅接收限时上传请求，不转发官网 Bearer 或 Cookie。
- READY 之前取消或失败会取消上传、释放预留配额并清理临时包；已完成的官网版本保留。
- 若最后设置当前版本或入库失败，保留同一资源和版本，点击“完成加入资源库”只补做收尾，不重新创建或重传。恢复状态可跨窗口隐藏和重开，整个客户端退出后不持久化，已上传版本仍可从官网“我的资源”查看。

主要源码入口：`pet/companion_ui.py`、`pet/platform_dialog.py`、`pet/platform_upload_dialog.py`、`pet/platform_upload.py`、`pet/platform_upload_transport.py`、`pet/platform_model_package.py`；Go 权限边界位于 `web/backend/internal/oauth/` 与 `web/backend/internal/api/`。OpenAPI、Go/TS 类型及授权页已同步，无新增数据库迁移。
