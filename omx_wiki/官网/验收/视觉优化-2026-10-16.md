# 官网视觉与交互优化验收 · 2026-10-16

本轮使用 `$design` 与 `$frontend-ui-engineering`，先检查现有实现和真实浏览器效果，再完成首页与公共控件的视觉优化。设计契约见 [DESIGN.md](../../../DESIGN.md)。适用官网；客户端 Qt 界面和业务服务不在本次修改范围。

## 现有设计分析与采用方案

原有暖白、草绿与黑金玄司角色已经形成产品识别，继续沿用。实测问题包括：导航、首页和正文宽度不同；移动导航常驻两行；辅助说明偏小；窄屏区块标题与右侧链接挤压；当前位置缺少提示；次按钮 hover 不统一。

据此统一内容对齐线、字级、按钮和表单；保留真实角色和下载主操作；将日常能力改为条目式阅读；手机使用内联折叠菜单。最后的对比度检查发现原辅助文字在浅绿背景上只有 4.36:1，统一调整辅助文字为 `#5b675a`，实测达到 5.00:1。

## 实现与功能边界

- `src/app/page.tsx`、`home.css`、`src/features/home-sections.tsx`：拆分首页说明区与专用样式；统一插画、文字与页脚对齐；插画说明不再与角色重叠；首页继续服务端渲染。
- `src/app/globals.css`：共用颜色、1200px 内容宽度、边距、按钮/输入/focus/disabled 状态；筛选栏在 900px 以下两列、640px 以下单列。
- `src/components/navigation.tsx`：当前页标记、手机菜单、Escape 关闭与焦点恢复、路由变化重置。按断点交替显示账号入口，让视觉顺序与 Tab 顺序一致；继续复用原 `useMe` 与查询缓存。
- `src/features/resources.tsx`：搜索、类型、标签位于提交按钮之前；Enter 筛选、翻页条件与缓存行为保留；资源标题改为 h2，修正列表标题层级。
- `src/app/layout.tsx`：复用已有品牌图标作为 favicon，消除原 404。
- `web/scripts/verify-design.mjs`：复用现有 Playwright/Chrome，保留可重复执行的响应式、键盘、筛选、工作台和文字对比度检查。

下载、功能、资源库、登录、工作台和页脚入口保留；账号、上传、授权下载、Go API 与客户端逻辑保持原实现。未增加依赖、外部字体或浏览器 Live2D 运行时。保留用户已有 `next-env.d.ts` 改动和未跟踪角色工程/素材。

## 复现与限制

按 [本地运行说明](../本地开发与运行.md) 启动官网与 API，再从仓库根执行：

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node web/scripts/verify-design.mjs
```

可用 `WEB_URL` 指定本地预览端口；本次生产构建的页面回归使用 `http://localhost:3001`。常规开发预览保留在 `http://localhost:3000`。本机首次构建遭遇 Next 遥测配置的 EXDEV，按现有开发约定设置 `NEXT_TELEMETRY_DISABLED=1` 后通过，未改动依赖或机器全局配置。临时生产页面检查使用 `next start`，其启动日志提示项目配置为 standalone；本轮未验证独立部署打包。

本轮不发送真实邮件、不创建真实账号、不提交资源、不下载或覆盖用户模型；工作台与异常状态只替代独立浏览器中的 GET 响应。没有重跑注册、邮件、上传与授权下载的完整业务闭环，不能将本轮视觉验收作为这些业务的新闭环证明。未部署公网、重新打包或更新已安装客户端。
