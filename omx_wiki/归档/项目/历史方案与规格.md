### 目标与范围

本事项直接来自本次桌面 AI 请求，是独立项目，不从既有接单计划派生。拟在当前项目仓库内开发。

用户已经确认：结合鼠标附近的屏幕内容理解操作，仅在本机处理。需要桌宠外观、可直接编辑的系统提示词和人设，以及不妨碍日常工作的运行方式。

推荐首版采用像素猫外观、文字气泡与动画反应。语音、摄像头和持续视频流不属于此次已明确提出的核心需求。

### 本机核验

通过 Windows CIM、磁盘查询和 `nvidia-smi` 获取；以下空闲量是调研时的瞬时值。

| 项目 | 实测 |
| --- | --- |
| 操作系统 | Windows 11 专业版 |
| CPU | i9-13980HX，24 核、32 线程 |
| 内存 | 总计约 31.6 GiB，空闲约 10.3 GiB |
| GPU | RTX 4070 Laptop，8188 MiB 显存，已用约 2547 MiB |
| 磁盘空闲 | C 约 30.2 GiB；D 约 50.5 GiB；E 约 24.7 GiB |
| 构建工具 | 已找到 Git、Node、pnpm；PATH 中未找到 Rust/Cargo 和 CMake，需进一步检查或安装 |

官方 PyTorch 实时演示列出至少 28GB NVIDIA 显存；官方 llama.cpp-omni 实时方案列出 NVIDIA 至少 12GB 显存。这两个实时方案的公开要求均高于本机配置。[模型官方说明](https://huggingface.co/openbmb/MiniCPM-o-4_5)

因此推荐先验证同一模型的量化图文推理。不能把“可以加载量化权重”当作“已经达到低延迟、低占用”；尚无本机推理测量结果。

### 模型与资源方案

- 模型：官方 `openbmb/MiniCPM-o-4_5-gguf`，语言权重选择 `MiniCPM-o-4_5-Q4_K_M.gguf`；接口查询大小为 5,026,714,400 字节，约 5.03GB / 4.68GiB。另需官方匹配的视觉投影文件，不能只下载语言权重。
- 推理：采用 llama.cpp 本地服务，使用官方图文部署路线。服务只绑定本机回环地址，关闭云端回退。安装时锁定通过图像测试的版本。[官方图文部署指引](https://github.com/OpenSQZ/MiniCPM-V-CookBook/blob/main/deployment/llama.cpp/minicpm-o4_5_llamacpp.md)
- 存储：建议模型保存至 `D:\AI\Models\MiniCPM-o-4_5`，项目源码保存在上述 E 盘项目目录。安装前核实完整下载清单、构建缓存和剩余空间；本轮尚未核实完整下载总量。
- 初始调优方向：低进程优先级、有限 CPU 线程、部分层放入 GPU、单请求并发、短输出、短上下文。以模型新增显存约 3GiB 为起始调优目标，而非已经证明或能由一个参数严格保证的上限。
- 鼠标跟随由轻量逻辑驱动。只有停留、点击、拖拽结束等有意义事件才考虑看图；初始建议两次自动分析至少间隔 15 秒，可在设置中调整。
- 请求繁忙时合并事件，只保留最近任务；丢弃过期回复。可附当前事件前后最多两张局部画面，但必须经过延迟与内存测试。
- 全屏或资源紧张时暂停自动分析；暂停模式支持停止推理进程，释放模型资源。降低反应频率和速度是保护其他工作的必要取舍。

### 交互与隐私约定

- 在设置窗口直接修改名字、系统提示词、人设、回复风格和反应频率；保存后下次请求生效，重启仍保留。
- 桌宠和自动气泡不主动抢焦点；透明区域点击穿透。显式打开聊天或设置时才允许输入焦点。提供一键暂停和托盘退出。
- 默认静音、不自动打开聊天窗口；工作模式固定在屏幕边缘，全屏时隐藏或暂停。
- 只采集鼠标事件和所需局部画面。屏幕内容仅作为待解释的数据，不作为执行命令的指令；模型不接管鼠标键盘。
- 应用不主动把截图写入文件或日志，不向云端发送截图、提示词或行为记录。移除或禁用所用外壳中不需要的外网请求，并实际检查运行时连接。
- 日志保留启动、暂停、耗时、错误码和资源采样，不记画面、聊天正文和窗口标题；关键逻辑有注释。

### 验收依据与失败补救

1. 下载完成后校验文件，断网时成功完成真实图文问答，证明确实加载指定模型。
2. 使用虚拟测试窗口复现停留、点击、拖拽；保留事件与预期反应的人工基准，检验图像和事件是否对应。局部信息不足时允许表达不确定。
3. 修改系统提示词和人设后验证下一次请求与重启后的行为；检查过期请求不会覆盖新设置。
4. 检验连续输入、窗口切换、多显示器/DPI、点击穿透与全屏暂停；自动反应导致的焦点抢占应为 0 次。
5. 在相同日常应用负载下比较关闭桌宠、待机、图文推理三种状态，记录 CPU、内存、显存、响应耗时及用户对卡顿的实际感受。
6. 检验暂停能终止采集和推理、释放模型资源；运行时无未经预期的非本机网络连接。

如本机无法同时满足有用的反应速度和可接受的工作流畅度，停止追加高负载功能，提交实际测量结果，由用户选择更低频、手动触发或其他方向。不得自行更换用户指定模型，也不得声称“完全不影响性能”。

### 交付能力

1. 本机看图与聊天：优先验证 Qwen3.5-4B Q4_K_M + 匹配视觉投影，通过 llama.cpp CUDA 12.4 运行；这是功能替代，不能宣称所有任务质量与 MiniCPM 完全相同。
2. 本机语音：SenseVoice int8 识别中文，Melo 中英合成语音，Kokoro int8 为可选。连续对话按钮开启麦克风，静音结束一轮，播报阶段暂停识别避免声学回声；按钮可停止播放和收音。应用启动时不自动开麦。
3. 使用 Python/PySide6 原生 Windows 窗口适配本地引擎。2026-09-13 按用户参考图改为“玄司”透明立绘与轻微身体动画。初版 NekoAI 猫咪精灵、定义和许可及 `upstream-nekoai` 保留供追溯；不宣称这是原版 NekoAI 二进制。
4. 可编辑名字、人设、系统提示词、观察间隔、宠物大小、语音音色和语速。保存后生效并在重启后保留；不持久化屏幕、麦克风录音或聊天正文。
   2026-09-14 增加软件内形象替换菜单：支持静态图片及透明 GIF/WebP/APNG，先预览再应用，可恢复默认玄司；导入副本保存在本机，动图循环播放，应用不打断当前会话。
5. 鼠标停留、点击、拖拽结束后读取鼠标所在显示器的完整画面，长边最多 1600 像素，可切回周围裁剪；单并发、限频和过期取消。文字/动作回应；自动观察默认不朗读，手动及语音对话按开关朗读。
6. 桌宠与自动气泡不抢焦点，透明区域穿透；只有用户打开控制面板才取得输入焦点。全屏及资源不足暂停自动观察，一键休眠停止模型释放资源。
7. 长期记忆只存用户明确要求记住的事项或手动编辑的文本；可编辑、清空和重启恢复。短期会话仅在内存，清空记忆会取消当前任务并清掉短期上下文。

### 结构及约束

`pet/` 放应用模块，`tests/` 放有意义的逻辑和生命周期测试，`scripts/` 放下载及验收脚本，`assets/neko/` 放上游精灵和定义，`runtime/` 放已校验推理引擎，模型放 `D:\AI\Models\desktop-pet`。

Python 3.13，异步 HTTP 与子进程；推理、语音和文件操作离开 UI 线程。回调只入队；所有 Qt 窗口操作在主线程。模块超过约 300 行且职责可拆分时拆分。关键路径有中文注释和无敏感正文的日志。

服务只监听 `127.0.0.1`，每次启动随机会话凭据，不写到文件。运行期 HTTP 客户端禁用环境代理。屏幕文字作为不可信内容，模型输出仅显示/朗读/映射到预设动作，绝不执行系统命令。下载仅取公开仓库，权重及发布包验证 SHA256。

直接依据用户本次请求及澄清：由模型理解用户是否希望桌宠停止或恢复说话，不用用户输入关键词匹配；只控制朗读，保留已经开启的麦克风，继续显示文字。范围限于本桌宠，与工作区接单计划无关。

已查阅当前 llama.cpp 官方 [GBNF 说明](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md) 和 [服务接口源码文档](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)；本机引擎为 build 10930（56381e407），实际兼容性以本机验证为准。

验收包括其他声音开口前阻止/中途打断/静音恢复/检测失败、自身声音排除、参数传递与越界、日志轮转与有界显示、热键冲突和注销、右下角位置及双窗口聊天同步。测试仅使用虚拟内容；本轮不改流式语音，不改用户长期记忆。
