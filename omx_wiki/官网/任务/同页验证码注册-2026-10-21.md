# 同页邮件验证码注册

2026-10-21，用户批准将注册改为同页输入邮箱、验证码、密码，取码后原地完成注册并自动登录；昵称默认“新朋友”，进入账号设置后可修改。复用 PostgreSQL 和现有 SMTP/MAIL worker，不增加 Redis 或依赖。

## 接口与数据

- `POST /api/v1/auth/registration-codes` 输入 `{email}`，202 返回 `{challengeId,expiresAt,resendAt}`；取码阶段不创建账号或会话，响应不包含验证码。
- `POST /api/v1/auth/registrations` 输入 `{email,challengeId,code,password}`，201 返回已验证的普通用户并设置新的安全会话 Cookie。验证码消费、用户和会话同一事务，失败全部回滚；已存在账号不会被覆盖或自动登录。
- 新迁移 `00011_registration_codes.sql` 保存挑战 HMAC 摘要、邮箱摘要、过期时间、错码次数及持久发信额度。随机码使用 Go `crypto/rand` 均匀生成六位 ASCII 数字，保留前导零，十分钟有效，五次错码后失效。
- 邮箱规范化后共享六十秒发送间隔、每邮箱五次/小时、每来源 IP 二十次/小时。额度窗口从首次发送起算一小时，支持多进程，重启不清零。旧注册与旧邮箱验证重发共享相同额度；验证重发对存在、不存在及禁用账号采用一致响应，防止通过冷却状态探测账号。
- 同邮箱重发使旧 challenge 失效。worker 在 SMTP 前检查 challenge 是否有效；任务结束继续沿用既有邮件正文清理。挑战表只保存带服务端密钥的摘要，待发送邮件正文短暂保留明文验证码；不是整个数据库只含摘要。应用回滚后的旧 worker 可能投递已经失效的邮件，注册接口仍拒绝过期/失效验证码。
- 旧链接验证和找回密码保留，密码规则继续共用服务端十二至一百二十八字符配置。既有用户登录、权限及管理员提升方式不变。

## 前端行为

邮箱、获取验证码、验证码和密码始终保留在注册页。发送请求不包含密码；错误留在相关字段旁，输入保留。重发依据服务端时间倒计时，结束后清理计时器；修改邮箱立即清除当前验证码与挑战，晚到响应不能绑到新邮箱。收据运行时校验编号和有效时间；坏收据不能成为注册凭据。成功后刷新身份及个人查询，再返回经过站内路径校验的原任务。旧注册表单分支已移除，登录、密码找回和旧邮箱链接页面仍可使用。

## 验证证据

- 隔离 PostgreSQL 迁移 1–11；完整 `go test -p 1 -count=1 -json ./...` 97 项顶层、含子测试 192 项通过，零失败、零测试跳过。覆盖并发消费、前导零、五次错误持久锁、重发、邮箱大小写、原有账号隔离、队列与会话失败回滚、额度与旧接口一致响应，以及失效邮件跳过 SMTP。
- TypeScript、ESLint 和四十页生产构建通过；真实 Chrome 合成接口八组通过，覆盖晚到响应、五类损坏收据、错误留稿、冷却、重发、导航身份与四种宽度。
- 真实 Chrome → Go → PostgreSQL → worker → 本机 Mailpit → 自动登录五组通过。取码不建用户，错码计数入库，正确码直接回原页面，刷新后会话保留；本次合成用户已清理。
- 旧注册密码回归脚本更新并通过六组；账号布局、ARIA、键盘、密码显隐和真实找回密码十三组通过。只向隔离本机 SMTP 发信。
- 独立安全复核通过；修复旧验证接口的邮箱枚举差异。具体策略数值为本产品选择，不冒充认证标准规定。
