# 本地运行与邮件测试约定

核对日期：2026-10-15。以下是当前本机环境与已验证约定，端口和运行状态不代表其他机器或后续会话。

## 当前入口与数据

| 服务 | 本机地址或用途 |
| --- | --- |
| Next 前端 | `http://localhost:3000` |
| Go API | `http://127.0.0.1:8080` |
| PostgreSQL | `127.0.0.1:15432`，复用 `web/.runtime/postgres` 原数据目录 |
| Mailpit | SMTP `127.0.0.1:1025`，界面 `http://127.0.0.1:8025`，供本地隔离测试使用 |
| 上传闭环测试 API | `127.0.0.1:8081`，需单独启动并使用测试库、测试 worker 和 Mailpit；验收结束后已停止 |

官网使用 `localhost:3000` 作为站点来源，避免随意切换为 `127.0.0.1:3000` 造成来源、Cookie 或授权地址不匹配。

原 PostgreSQL 54329 端口在本机无法绑定，已通过 `run-dependencies.ps1 -Portable -PostgresPort 15432` 恢复；`web/.env` 的数据库地址已匹配。脚本默认值及旧验收章节可能仍为 54329，复现当前环境应以此处 15432 和本地配置为准。保留原数据目录，不重新初始化已有库。

- `xuansi`：主开发站点数据。
- `xuansi_test`：Go 自动化测试专用；测试会清理隔离库，不可指向主库，也不并行运行多组共享该库的测试。
- `xuansi_upload_check`：客户端真实上传闭环专用，避免与 Go 测试互相清空数据。

## 启动入口

在项目根目录启动便携依赖；API、worker 和前端各用独立终端启动：

```powershell
.\web\scripts\run-dependencies.ps1 -Portable -PostgresPort 15432
.\web\scripts\run-dev.ps1 -Service api
.\web\scripts\run-dev.ps1 -Service worker
.\web\scripts\run-dev.ps1 -Service frontend
```

`run-dev.ps1` 加载本机 `web/.env`。桌宠通过项目“启动桌宠”入口运行。常规 Docker 依赖入口、工具准备和部署边界见 [web 运行说明](官网/本地开发与运行.md)；本次验收使用本机便携环境。

## 邮箱与密码行为

本机主站已按用户授权配置 QQ SMTP：`smtp.qq.com:587`、STARTTLS。真实登录账号、授权码和发件配置只在 Git 忽略的 `web/.env` 中维护；知识库、配置示例、报告和日志仅记录配置方式与状态。

应用把邮件写入 PostgreSQL 队列，由 Go worker 发送。QQ 配置验收时证书校验、TLS 1.3、AUTH PLAIN 通过；发给配置者本人的测试邮件任务为 DONE、尝试 1 次、任务正文已清除。这证明服务器接受邮件，尚不能证明收件箱实际收到。

注册邮箱验证使用有效期 1 小时的一次性邮件链接，并非数字验证码。创建、重置和修改密码共用 12～128 个 Unicode 码点规则，前端从 `/api/v1/auth/config` 获取；旧密码登录保持兼容。真实 SMTP 模式隐藏本地收件入口，本地 Mailpit 模式显示入口。

## 自动化测试约束

主站当前为真实 SMTP 模式。注册、找回和客户端上传端到端验收使用独立数据库、隔离 API/worker 与 Mailpit，不在主站创建随机验收账号或发送测试邮件。`verify-platform.mjs`、`verify-auth-regression.mjs` 会在创建账号前检查本地邮箱模式，遇到真实 SMTP 配置会提前停止。

隔离测试不得读取或覆盖用户 Windows 凭据，不把密码、Cookie、令牌、授权 URL 或邮件正文写入报告。上传测试仅在临时目录安装和比较文件，保留用户模型、编辑工程及原有开发数据。

当前源码中客户端连接、上传及验收结果见 [[客户端-live2d-直接上传验收-2026-10-15]]；完整测试步骤与隔离路由说明见 [开发验收](官网/验收/开发验收.md)。
