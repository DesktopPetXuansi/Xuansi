# 桌宠客户端直接上传 Live2D

用户已选择在现有 desktop-ai-pet 客户端中完成上传。目标流程：打开官网资源库，点击上传本地模型；首次通过浏览器连接官网账号，选择模型文件夹或入口文件，确认默认资料后上传。

## 方案

- 复用 PKCE、Windows 凭据管理器和官网现有资源/版本/上传接口。
- 上传操作显式申请 `resources:read resources:write`；既有只读令牌不升级，账号、管理员、发布和删除资源权限不开放。
- 自动收集 `.model3.json` 引用的运行文件，保留相对目录，只打包模型所需文件。压缩、磁盘与网络 I/O 在后台执行，源文件不改动。
- 默认名称来自模型入口文件名或选择的目录名、作者来自本人账号、版本号为 `1.0.0`；许可使用现有默认提示，用户可编辑。
- 上传后等待官网校验，自动设置当前版本并加入本人的资源库。提供进度、取消、错误说明和官网查看入口。

## 任务与验收

- [x] Go 授权与权限边界：授权页明确上传能力；只读和跨账号访问仍被拒绝；写令牌完成完整上传流程，无需 Cookie/CSRF；刷新与撤销保留权限边界。
- [x] 本地模型整理：支持入口文件和模型文件夹，忽略编辑工程和无关文件；缺引用、多入口、越界路径、链接、超限均在上传前失败；不修改源模型。
- [x] 客户端上传流程：异步流式上传；验证后自动设当前版本与入库；取消和失败释放上传配额，临时文件清理；存储上传不泄漏官网凭据。
- [x] 客户端界面与验证：首次连接后可直接上传，后续复用授权；真实 Qt 回归、Go PostgreSQL 测试、客户端真实 HTTP 上传与后台校验通过；通用说明更新。

验证完成于2026-10-15。真实Qt窗口经浏览器PKCE连接隔离Go服务，项目玄司模型上传、后台校验、设置当前版本、入库、重新下载与源文件逐项一致、离线读取通过；测试未使用用户已保管的授权。独立复审发现的未知字段附件收集与最后入库重试问题均先以红测复现，修复后复审0问题；目录链接的入口搜索另有回归覆盖。详细结果见 [开发验收](../docs/开发验收.md)。

## 验证约束

自动验证使用隔离 PostgreSQL 测试库和本地 Mailpit，不向已配置 QQ SMTP 发送测试账号邮件，不读取或覆盖用户已保管的授权。用户已有模型和编辑工程不修改，不发布公网服务或新客户端发行。
