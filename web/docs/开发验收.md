## 实际闭环

`verify-platform.mjs` 在本机创建随机验收账号，走注册表单、worker SMTP 邮件、一次性邮箱确认、登录和工作台。图片资源通过浏览器创建、上传、后台轮询和资料编辑；第二个账号读取私有资源被拒绝。

MODEL、MOTION、EXPRESSION、ANIMATION 走真实 API 上传、重复完成、worker、manifest 和下载字节/SHA-256 检查。图片加到同一资源库，因此客户端实际下载并安装全部五种类型。模型夹具复制项目现有导出素材并添加空可选引用和说明附件，原始素材未修改，仅作私有本机验收。

Python 客户端自行生成 PKCE、随机回环监听与授权码请求；浏览器完成显式同意，Go 实际兑换令牌。浏览器授权 URL 和令牌仅在进程内传递，不打印或写报告。客户端流式下载、逐文件验证和原子安装后，由实际 Live2D SDK 试载模型、启动动作、应用表情并输出画面；临时配置重新加载后离线校验和应用通过。客户端真实注销后，旧访问令牌立即返回 401。

管理员 CLI 只提升本机新建且已验证的验收账号。浏览器发布本机生成的 CC0 图片并验证匿名访问，模型素材保持私有。浏览器创建 BETA 测试草稿、编辑更新说明，并确认公开版本接口返回 404；没有发布测试客户端版本。五个管理员页面正常，编辑说明产生对应审计记录。

密码恢复通过真实发件、浏览器恢复表单，旧网站会话失效，新密码登录成功。完整流程无未捕获浏览器异常。

## 复审修复

- 管理员停用后，所有者不能自行恢复；已有下载票据也重新检查停用和授权撤销。
- 资源库数据库失败返回错误，资源、版本依赖与发行安装包批量加载，单个版本不扫描整个版本列表。
- 上传、取消、规范包超额和相同封面替换使用持久清理记录，避免残留对象或误删当前文件。
- CSRF 准备复用合法已有 cookie，避免并发请求互相覆盖令牌；针对旧令牌与当前 cookie 的写入回归通过。
- 前端资料编辑不发送仅创建时允许的 kind，版本草稿编辑只发送 releaseNotes，可选表单空值不变成字符串 `null`。
- Go/Python 对空的可选 Cubism 引用、最低版本、文件数与允许附件类型统一，必需引用仍拒绝空值。共享夹具和两端回归通过。
- 客户端模型切换、平台设置持久化、窗口关闭与后台取消保持一致，外部模型不暴露玄司专用动作。
- Go 工具链、JOSE 和 OpenTelemetry 升级到包含安全修复的版本，静态 WebP 明确注册解码器。生产代理保持 `no-referrer`，避免一次性邮件链接作为来源泄露。

govulncheck 的模块信息仍列出 x/crypto 中旧 OpenPGP 包的报告；当前源码依赖图没有导入该包，扫描没有调用路径命中。该报告涉及不再维护的 OpenPGP 包，不能以模块提示推断本项目使用 Argon2 的路径受影响。[Go 官方漏洞报告](https://pkg.go.dev/vuln/GO-2026-5932)

## 复现命令

先按 [运行说明](../README.md) 启动依赖、API、worker 和前端。Go 测试会清空其隔离库，只使用名称为 `xuansi_test` 的本机测试库，不要并行运行多组共享该库的测试。

```powershell
# 项目根目录：普通回归、静态检查、原生 SDK。
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check pet tests web/scripts/prepare-fixtures.py web/scripts/verify-client-api.py
$env:PET_PLATFORM_NATIVE='1'
.venv/Scripts/python.exe -m pytest tests/test_platform_native.py -q
Remove-Item Env:PET_PLATFORM_NATIVE

Push-Location web/backend
$env:TEST_DATABASE_URL='postgres://xuansi@127.0.0.1:54329/xuansi_test?sslmode=disable'
go test ./... -count=1
go vet ./...
go build ./cmd/...
go run golang.org/x/vuln/cmd/govulncheck@v1.2.0 -json ./...
Pop-Location

Push-Location web/frontend
pnpm typecheck
pnpm lint
pnpm build
pnpm audit --prod
Pop-Location

# 独立终端用 run-preview.ps1 运行生产构建，再执行浏览器验证。
.venv/Scripts/python.exe web/scripts/prepare-fixtures.py
node web/scripts/verify-browser-public.mjs
node web/scripts/verify-platform.mjs
.venv/Scripts/python.exe web/scripts/verify-installer-payload.py --compiler build/tools/inno-7.1.0/tools/ISCC.exe
git diff --check
```

若 Go 官方模块代理在本机不可达，可在当前验证终端设置 `GOPROXY` 为可达代理；本次没有修改全局 Go 配置。集成脚本只允许回环来源，会创建本地测试账号、资源和未发布草稿，令牌与随机密码不落盘；原生资源安装在临时目录，退出后清理，不覆盖用户保管的凭据或桌面设置。

复现输出位于忽略目录：`web/.runtime/integration-report.json`（19 项断言、5 种类型、浏览器异常 0）、`vuln-report.jsonl` 与 `screenshots/`。报告只保留断言与资源 UUID，不保留密码、Cookie、邮件正文或授权 URL。官方 standalone 的静态文件复制方式参见 [Next 文档](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)。
